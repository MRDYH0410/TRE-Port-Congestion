# Shared Section 5.1 data layer

This directory is the only shared data location for the experiments that will
later be added under Sections 5.2 and 5.3.

- `raw/` contains bit-identical frozen source files and curated official/event
  anchors. Raw files are never rewritten.
- `processed/` is generated only by the clean-room construction in
  `python -m experiments.data.prepare`.
- `manifests/` records source hashes, evidence boundaries, output hashes, and
  every data-quality assertion used by the build.

The build checks the manuscript's declared grain, row/field counts, missing
cells, duplicate keys, date coverage, Monday-week aggregation, complete-week
window, event-window length, retained zero-activity counts, GPR monthly
continuity, gateway scales, network exposure, committed shares, and the
right-censored event marker.

The processed data do not assert more than the sources identify. In particular,
PortWatch is an AIS-derived activity proxy rather than handled TEU or observed
diversion; official nameplate values are allocation anchors rather than weekly
service; Jebel Ali is retained only as a comparator; and the event marker does
not turn renewed-closure duration into an observed value.

The raw event file contains only the two reported advisory dates and their
sources. The 0.164 serviceability and 0.836 severity values are stored in the
manifest as current-manuscript estimates to be independently regenerated by
the first data/event-validity experiment; no old processed trajectory is used.

The common data build creates continuous GPR features using the row-count-
consistent 24-month rolling volatility construction. It intentionally does not
invent the jump threshold. The first information experiment must declare a
positive `jump_sigma` and call `add_gpr_jump_indicator` before HMM fitting.
